Jak pusty formularz staje się JSON-em e-usługi COI

Python 3.14 + FastAPI. Model rozumie dokument, kod pilnuje formatu COI. Modele z otwartymi wagami na Eden AI, jedyny wymagany sekret to EDENAI_API_KEY.
wejście / wyjście wywołanie modelu (Eden AI, API zgodne z OpenAI) kod deterministyczny, z testami co idzie do następnego kroku
Główna ścieżka: POST /api/forms/convert (app/pipeline.py)

1. Upload

app/upload.py, security.py
  • jeden plik, tylko w pamięci
  • limit rozmiaru, nazwa, rozszerzenie, sygnatura bajtów
  • JWT przy AUTH_ENABLED=1
bajty + nazwa

2. Odczyt stron

app/llm/transcribe.py
  • każdy format → obrazy stron (PDFium; pliki biurowe przez LibreOffice)
  • plik biurowy, któremu LibreOffice zgubi tekst: jego własny tekst
  • Qwen3.5-397B-A17B: jedno wywołanie na stronę, 4 naraz
  • odczyt 16 ostatnich plików zostaje w pamięci (sha256), słowniki nie płacą drugi raz

6. Reguły COI

  • schemat JSON COI

200: JSON COI

Modele na Eden AI (otwarte wagi)

app/llm/client.py, LLM_MODEL i TRANSCRIBE_MODEL w konfiguracji
  • odczyt: Qwen3.5-397B-A17B (wizyjny, Apache-2.0)
  • planer: GLM-5.2 (tekstowy, MIT), 2 przebiegi na formularz, myślenie wyłączone
  • średnio na formularz: {{CZAS_FORMULARZ}}, {{KOSZT_FORMULARZ}}
  • te same wagi można postawić u siebie: LLM_BASE_URL

Propozycje słowników (bonus II)

POST /api/dictionaries/proposals, app/dictionaries.py
  • strona wysyła plik jednocześnie do konwersji i tutaj
  • ten sam odczyt stron, bez drugiego płacenia
  • model proponuje słownik, kod zostawia tylko wartości z dokumentu
  • „Dodaj” zapisuje go w katalogu i podpina pod pole

Strona dla urzędnika (bonusy IV, V, VI)

app/static/index.html, preview.html, editor.js
  • historia plików, kilka plików naraz, ZIP wszystkich JSON-ów
  • oryginał obok e-usługi, jak zobaczy ją obywatel
  • cytat i „Źródło” pod polem, panel „Edycja”
  • każda zmiana → POST /api/forms/check, z problemem nie da się pobrać JSON-a
